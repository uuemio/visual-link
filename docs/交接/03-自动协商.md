## 接口约定

- `automatic.capabilities(observed, config) -> Capabilities`：`observed`来自`discovery.device_capabilities`；`modes`为本端显示候选，`rx_modes`为本端BGR3采集候选，layout=1，versions=(2,3)。仅纳入明确声明且编解码器支持的尺寸，过滤交错/非32位Windows显示声明。`candidate_modes`可选，如`[[1920,1080],[1920,1200]]`，省略则允许两种；它是候选限制，不是已选档位。
- `common_modes(tx_caps, rx_caps)`取`tx_caps.modes ∩ rx_caps.rx_modes`并按像素数降序。`ModeSession`的`round/indices/local_status/peer_status`表示选档轮次、按UUID排序的两方向索引、本端/对端的tx/rx验证结果（0等待，1成功，-1失败）。失败只递增对应方向索引；旧轮次STATUS忽略，候选耗尽明确失败。
- `with automatic.startup(config, directory, seconds, display) as (selected, session, modes): ...`：保持`apply_display_mode`作用域；selected内tx_mode/rx_mode为独立尺寸，session为同UUID的`NegotiationSession`，包含`selected_modes`及`directional_timings`。通常直接调用既有`bootstrap.exchange(..., calibrate=True, negotiate=True, input_file=...)`，内部已接入该上下文。
- `NegotiationSession.direction(sending)`返回`[config_id,profile,fps,window,mode_id,width,height,layout]`。按UUID排序方向0/1，1080p配置ID为1/2、1200p为3/4；mode_id=`gray16-1920x1080-l1`或`gray16-1920x1200-l1`。可用`ImageParameters(width=row[5],height=row[6])`重建参数；不得以本端tx参数解释rx。业务头仍为v2，RS/16级灰度/交付确认不变。
- `signal_lock_seconds`为每次应用后的本地rx标定等待秒数，默认25；总时长仍受`--seconds`约束。采集尺寸匹配不代表信号锁定；黑帧或标定失败时重开，超时后报告失败。尺寸不符时继续尝试解读控制图以接收回退SELECT。初始控制画布可独立于业务尺寸，软件验证覆盖1600×900。

Agent 4的读取入口：

- 启动期间读`startup/progress.json`：`state`为capabilities/mode_calibration，含round、indices、selected_modes、local_status、peer_status、actual_capture。
- 业务期间读根`progress.json`：`modes.tx_mode/rx_mode`为本地方向尺寸，`modes.actual_capture.actual`为实测rx尺寸，`modes.actual_capture.capture`含reported FPS与actual/sampling；`configurations.directions`为提交配置，现有进度/transport字段继续有效。
- 最终读根`result.json`的同名`modes/configurations`及connection_ready、send_ready、receive_complete、transport；`startup/result.json`保存相同模式、身份和`measured_ms/peer_measured_ms`。驱动FPS=0表示未提供，不能显示成无采样。声明、当前桌面输出、实际采集应分别展示。
