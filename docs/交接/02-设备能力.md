## 接口约定

- `discovery.device_capabilities(config) -> dict`：不依赖当前尺寸等于配置尺寸。`schema=1`；`display/capture`均含`api,device,declared,current_output`，`observed_monotonic_ns`仅供本机日志排序。显示含`monitor`索引，声明项`width,height,refresh_hz`，Windows补充位深/交错，Linux补充mode name/current。尺寸单位像素，刷新率Hz。
- `capture.declared`项含`format,native_format,width,height,fps,fps_min,fps_max`。跨平台`format='BGR3'`对应Windows原生`MEDIASUBTYPE_RGB24`；`fps`为驱动明确给出的速率列表（Windows媒体类型默认值），Windows上下限来自IAMStreamConfig范围，不能把默认列表当成完整离散集合。V4L2连续尺寸用`size_range`原文表示，不伪造离散候选。其他格式保留原生标识。采集帧率是USB输出采样率，不等同显示刷新率。
- `display.current_output`含实际桌面`width,height,refresh_hz`，Windows还含`signal.source/active/total/refresh/scaling`；Linux含`scale/transform`。`capture.current_output`是驱动当时输出，DirectShow特指未连接pin的默认媒体类型，不证明HDMI输入。V4L2 `input_timing`保存query-dv-timings原始返回；本卡不支持该ioctl。
- `with discovery.apply_display_mode(config,refresh_hz=None) as report:`：使用`image_parameters(config,'tx')`，只应用所选输出声明模式；报告`before,current_output,changed,device,api`。Windows默认优先60Hz、检查物理identity；Linux等GTK几何同步后才允许显示。作用域正常/异常退出均恢复原模式。调用方须将整个标定/传输阶段置于作用域内，不能在context退出后提交候选。
- `discovery.refresh_capture(config,directory,require_match=True) -> (updated_config,image,probe)`：调用前关闭旧采集generator/worker，目录已新建。隔离worker重开卡、请求rx尺寸、丢弃5帧后读取实际BGR尺寸；返回配置仅更新`rx_mode`，不修改传入config或tx。`probe.json`保存请求、reported、actual、是否匹配；`device.json`保存format/shape/strides及`sampling.frames_read/elapsed_seconds`。尺寸不符或不受步骤1支持时留证后抛错。`require_match=False`仅用于诊断。软件读取数和时间含预热，不是HDMI时间戳。
- 既有`capture_frames/capture_one`仍默认严格尺寸；仅观察入口使用`strict=False`。格式、uint8 BGR及资源释放检查不变。新增采集actual/sampling也会进入既有bootstrap的probe记录。
- CLI：`capabilities`、`apply-mode [--input 原生PNG] [--refresh-hz Hz]`、`capture-mode`，均使用既有`--config/--output`及新目录约定。Windows交互脚本支持前两项；完整命令见HARDWARE。

```python
from visual_link.discovery import device_capabilities, apply_display_mode, refresh_capture
from visual_link.core.image import image_parameters
from visual_link.calibration import pattern, measure, receive_wire
from visual_link.core.protocol import decode

caps = device_capabilities(config)
# 两方向分别按对端声明选出候选；这里仅示意本端tx1200、rx1080。
selected = dict(config, tx_mode={'width': 1920, 'height': 1200},
                rx_mode={'width': 1920, 'height': 1080})
with apply_display_mode(selected) as applied:
    # 在真实桌面显示本端tx标定图；对向显示就绪后，关闭旧采集并重开：
    actual_config, captured, probe = refresh_capture(selected, new_capture_directory)
    rx = image_parameters(actual_config, 'rx')
    calibration = measure(pattern(peer_seed, rx), captured, rx)
    # 后续实际业务帧：decode(receive_wire(next_capture, calibration, rx), rx)
```

## 接续任务

Agent 3从`device_capabilities`的display/capture声明生成每方向候选，过滤BGR3及步骤1支持尺寸；必须以模式应用、实际采集和标定成功作为提交条件。USB帧率不用于推断HDMI刷新率。输入变化可能暂时输出黑帧，尺寸相符仍必须等待并验证标定，失败才回退下一候选；不得提交黑帧模式。

将`apply_display_mode`作用域维持到会话结束，在模式切换前停止旧显示/采集，随后刷新实际rx参数、重建分片源/接收器与标定目标。接入CAPS/PROPOSE等模式身份并解除步骤1的非双1080p negotiate限制，完成不同方向模式自动协商与双向文件交付。本步骤未改CAPS/业务配置ID或网页；未把单向硬件帧验证当成步骤3端到端自动协商验收。
