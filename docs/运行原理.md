# 程序运行原理

程序把文件转换成灰度图像，通过HDMI显示；另一端用USB采集卡读取图像，再恢复文件。

两条链路分别负责Windows→树莓派、树莓派→Windows。文件数据和确认消息都通过视频传输，两端可以同时发送文件。

## 一次传输的流程

### 1. 启动

两端读取配置，打开采集卡和显示窗口，读取待发送文件的大小并计算SHA-256。SHA-256可以理解为文件的内容指纹，用于核对收到的内容是否一致。

### 2. 发现对端

两端显示包含身份和能力信息的控制图像。识别对方后建立会话，交换各自支持的参数。

### 3. 标定画面

双方显示标定图。接收端测出图像方向、位置偏移、有效区域及灰度识别阈值，让采集到的像素能正确还原为数据。

### 4. 协商参数

程序结合两端处理能力，分别确定两个方向的发送参数。Windows→树莓派和树莓派→Windows可以采用不同速度。双方确认就绪后开始传文件。

### 5. 文件变成图像

发送端逐片读取文件，每个满载分片为1,000,103字节，约1MB：

```text
文件分片 → 添加编号、长度和校验信息 → RS纠错编码
        → 字节交织 → 16级灰度图像 → HDMI显示
```

RS编码加入纠错信息，使接收端能修复一定数量的错误。交织将相邻字节分散到不同位置，减小局部图像异常对同一码块的集中影响。

### 6. 图像恢复为文件分片

接收端持续采集画面：

```text
采集图像 → 定位有效区域 → 识别灰度并还原字节
        → 逆交织 → 纠错与校验 → 按编号写入临时文件
```

同一张图可能被采集多次，程序会识别重复分片。分片也可以乱序到达，接收端按编号写入对应位置。

### 7. 确认和重传

接收端将已收到的分片编号写入ACK控制图像，通过反向视频链路反馈。

发送端同时保留多个等待确认的分片，超时未确认的分片会重发。程序根据确认延迟和重传情况调整发送速度与在途数量。

业务图像和控制图像交替显示，两个方向各自维护发送进度。

### 8. 完整文件确认

所有分片收到后，接收端在后台核对完整文件的长度和SHA-256，完成落盘并生成received.bin，再发送FINISH消息。

- ACK表示相应分片已收到。
- FINISH表示整个文件已校验并交付。

发送端收到FINISH后确认成功，并回送完成应答。

### 9. 保存结果并退出

程序按启动时指定的秒数运行。文件提前传完后继续应答对端，到时间后关闭显示和采集，保存结果与日志。

## 当前使用方式

每次会话每端发送一个文件，两端可同时进行。操作步骤见[使用说明](../使用说明.md)，协议细节见[协议文档](PROTOCOL.md)。

完整过程：启动 → 发现 → 标定 → 协商 → 图像传输与重传 → 文件校验 → 完成确认 → 退出。
