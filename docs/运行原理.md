# 程序运行原理

程序把文件转换成灰度图像，通过HDMI显示；另一端用USB采集卡读取图像，再恢复文件。

两条链路分别负责Windows→树莓派、树莓派→Windows。文件数据和确认消息都通过视频传输，两端可以同时发送文件。

## 一次传输的流程

### 1. 识别设备与当前画布

配置保存设备选择与候选模式；固定线格式和运行默认值由程序统一补齐。读取所选显示器的声明模式、当前桌面输出以及采集卡的BGR3声明模式。声明支持某尺寸不等于已实际采到该尺寸。

两端读取待发送文件大小和SHA-256，并在当前桌面画布显示身份与能力控制图，不要求预先手动切到业务尺寸。

### 2. 分别选择两个方向的模式

CAPS交换显示候选与采集候选。每个方向独立取发送端显示和接收端采集能力的交集，优先最大像素数。SELECT在原画布重复确认，双方收到后才切换，保持UUID和会话身份。

### 3. 应用模式、锁定采集并标定

发送端设置显示模式，接收端重开采集并读取实际帧尺寸。尺寸匹配后还要成功解出零错误标定图，测量编解码与处理耗时。黑帧或尺寸匹配不能替代标定成功。失败只回退相应方向的候选；无共同候选或超时则明确失败。

### 4. 提交配置

双方验证模式后交换REPORT测量值，通过PROPOSE/ACCEPT/COMMIT/READY提交两个方向的配置。每个方向绑定模式ID、宽高、布局版本、发送速度和窗口，发送与接收各自使用自己的图像参数。选定档位和测量值只保存在会话状态，退出后恢复原显示。

页面轮询`startup/progress.json`显示启动选档与标定状态，进入业务后以根`progress.json`的模式、实际采集、方向配置及传输统计为准，退出后读取`result.json`核验交付。

### 5. 文件变成图像

发送端逐片读取文件，满载分片容量由该方向有效像素与RS参数计算：1080p为1,000,103字节，1200p为1,111,500字节：

```text
文件分片 → 添加编号、长度和校验信息 → RS纠错编码
        → 字节交织 → 16级灰度图像 → HDMI显示
```

RS编码加入纠错信息，使接收端能修复一定数量的错误。交织将相邻字节分散到不同位置，减小局部图像异常对同一码块的集中影响。

### 6. 图像恢复为文件分片

接收端持续采集画面：

```text
采集图像 → 定位有效区域 → 识别灰度并还原字节
        → 逆交织 → 纠错与校验 → 按编号写入临时文件
```

同一张图可能被采集多次，程序会识别重复分片。分片也可以乱序到达，接收端按编号写入对应位置。

### 7. 确认和重传

接收端将已收到的分片编号写入ACK控制图像，通过反向视频链路反馈。

发送端同时保留多个等待确认的分片，超时未确认的分片会重发。程序根据确认延迟和重传情况调整发送速度与在途数量。

业务图像和控制图像交替显示，两个方向各自维护发送进度。

### 8. 完整文件确认

所有分片收到后，接收端在后台核对完整文件的长度和SHA-256，完成落盘并生成received.bin，再发送FINISH消息。

- ACK表示相应分片已收到。
- FINISH表示整个文件已校验并交付。

发送端收到FINISH后确认成功，并回送完成应答。

### 9. 保存结果并退出

程序按启动时指定的秒数运行。文件提前传完后继续应答对端，到时间后关闭显示和采集，保存结果与日志。

## 当前使用方式

每次会话每端发送一个文件，两端可同时进行。操作步骤见[使用说明](../使用说明.md)，协议细节见[协议文档](PROTOCOL.md)。

完整过程：当前画布引导 → 能力交换 → 双向候选确认 → 设置显示与锁定采集 → 标定与处理测量 → 提交配置 → 图像传输与重传 → 文件校验与交付确认 → 恢复显示并退出。
